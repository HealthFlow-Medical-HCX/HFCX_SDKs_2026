## Highlights

- Full HFCX protocol support: registry lookup → JWE encryption (hard-
  pinned RSA-OAEP-256 + A256GCM) → Keycloak bearer auth → POST to the
  gateway, with retry/backoff and typed-error mapping. Both sync
  (`HfcxClient`) and async (`AsyncHfcxClient`) variants.
- Recipient-side pipeline with four independently toggleable
  validation layers (BEARER / HEADERS / FHIR / EGYPTIAN), shipped via
  `RecipientHandler`.
- 27-entry `ErrorCode` catalog with a typed exception subclass per
  code — wire-format-identical to the Java SDK.
- 27 Egyptian governorates as a first-class `EgyptianGovernorate`
  enum.
- Two reference recipient apps under `docs/examples/`:
  `recipient-fastapi/` (FastAPI) and `recipient-flask/` (Flask).
- ContextVar-based correlation-ID propagation that survives `asyncio`
  task switches; functional parity with Java's MDC-based
  implementation under the same `correlation_id` key.

## PyPI install

```bash
pip install hfcx-sdk==1.0.0
```

The wheel is published as `hfcx_sdk` under the
`HealthFlow-Medical-HCX` PyPI organisation. Compile-time
dependencies: `httpx`, `cachetools`, `jwcrypto`, `cryptography`. No
optional accelerators required for any code path.

## Compatibility

| Component                          | Pinned version   |
|------------------------------------|------------------|
| Platform                           | 1.0.0            |
| Python                             | 3.10, 3.11, 3.12 |
| Egyptian FHIR IG package           | bundled in `fhir-ig/egyptian-ig.tgz` (synced from platform release at GA cut) |
| JWE algorithms                     | RSA-OAEP-256 / A256GCM (pinned, downgrade-attack guard) |
| Protocol header form               | mixed hyphen+underscore (Gap 7 backward-compat) |

`hfcx_sdk.bundled_ig_version()` returns the platform tag the bundled
IG was synced from.

for cross-SDK round-trip testing against the Java SDK during the
delivery sprints (P1–P6).

## Known gaps and follow-ups

- HAPI-equivalent full-IG profile validation is deferred. The
  hand-rolled `FhirValidator` enforces the same Egyptian-IG profile
  rules the Java SDK does; swapping to a full-IG validator over a
  bundled `egyptian-ig.tgz` does not change the public
  `FhirValidator` surface.
- `tests/integration/test_platform_mock_payer.py` cases remain
  `pytest.mark.skip` until the platform's `tests/integration/` Docker
  stack is wired into CI. The hermetic round-trip tests in
  `test_client.py` and the example-app integration tests cover the
  same matrix in-process.
- A reference JWKS-backed `BearerTokenValidator` is not bundled; this
  is intentional, so participants make a deliberate choice. A
  reference implementation can ship in a follow-up minor release.

## Acknowledgements

Behaviour was ported from the Java SDK's J1–J7 implementation rather
than rewritten from the platform spec — the protocol primitives, the
27-entry error catalog, and the four-layer recipient pipeline are
byte-for-byte cross-SDK invariant. Cross-SDK round-trip fixtures
under `tests/fixtures/cross-sdk/` close the loop with the Java SDK.
