## Highlights

- Full HFCX protocol support: registry lookup → JWE encryption (hard-
  pinned RSA-OAEP-256 + A256GCM) → Keycloak bearer auth → POST to the
  gateway, with retry/backoff and typed-error mapping. Async-only,
  per .NET convention.
- Recipient-side pipeline with four independently toggleable
  validation layers (Bearer / Headers / Fhir / Egyptian), shipped via
  `RecipientHandler`.
- 27-entry `ErrorCode` catalog with a typed exception subclass per
  code — wire-format-identical to the Java and Python SDKs.
- 27 Egyptian governorates as a first-class `EgyptianGovernorate`
  type.
- Reference recipient app under `docs/examples/recipient-aspnet/`
  showing how to host `RecipientHandler` behind ASP.NET Core 8
  minimal APIs.
- Correlation-ID propagation via `AsyncLocal<string?>` that survives
  `await` boundaries; cross-SDK MDC key `correlation_id` matches Java
  + Python.

`Microsoft.Extensions.Logging.Abstractions`. No optional accelerators
required for any code path.

## What changed since 0.x

This is the first GA release. The 0.1.0-alpha line was internal-only,
intended for cross-SDK round-trip testing against the Java and Python
SDKs during the delivery sprints (D1–D6).

## Known gaps and follow-ups

- HAPI-equivalent full-IG profile validation is deferred. The
  hand-rolled `FhirValidator` enforces the same Egyptian-IG profile
  rules the Java and Python SDKs do; swapping to a full-IG validator
  over a bundled `egyptian-ig.tgz` does not change the public
  `FhirValidator` surface.
- A reference JWKS-backed `IBearerTokenValidator` is not bundled;
  this is intentional, so participants make a deliberate choice. A
  reference implementation can ship in a follow-up minor release.
- `net10.0` multi-targeting is deferred to a follow-up minor release
  once the package metadata for the multi-target build is settled.
- Platform-integration tests (running against the platform's
  `tests/integration/` Docker stack) are not yet wired into CI; the
  hermetic xUnit suite covers the same matrix in-process.

## Acknowledgements

Behaviour was ported from the Java and Python SDKs' implementations
rather than rewritten from the platform spec — the protocol
primitives, the 27-entry error catalog, and the four-layer recipient
pipeline are byte-for-byte cross-SDK invariant. Cross-SDK round-trip
fixtures under `tests/HealthFlow.Hfcx.Sdk.Tests/fixtures/cross-sdk/`
close the loop with the Java and Python SDKs.
