## Highlights

- Full HFCX protocol support: registry lookup → JWE encryption (hard-
  pinned RSA-OAEP-256 + A256GCM) → Keycloak bearer auth → POST to the
  gateway, with retry/backoff and typed error mapping.
- Recipient-side pipeline with four independently toggleable
  validation layers (BEARER / HEADERS / FHIR / EGYPTIAN).
- 27-entry `ErrorCode` catalog with a typed exception subclass per
  code.
- 27 Egyptian governorates as a first-class enum.
- Self-contained Spring Boot recipient example (`hfcx-sdk-examples/`)
  plus three runnable examples under `docs/examples/`.

## Maven coordinates

```xml
<dependency>
    <groupId>eg.gov.healthflow</groupId>
    <artifactId>hfcx-sdk-client</artifactId>
    <version>1.0.0</version>
</dependency>
```

`hfcx-sdk-core` is published as a transitive dependency; depend on it
directly only if you want the protocol primitives without the
high-level client API.

## Known gaps and follow-ups

- HAPI-FHIR full-IG profile validation is deferred. Sprint J5 ships a
  hand-rolled validator that enforces the same Egyptian-IG profile
  rules; swapping to HAPI-FHIR with the bundled
  `egyptian-ig.tgz` package does not change the public
  `FhirValidator` surface.
- `PlatformMockPayerIntegrationTest` remains `@Disabled` until the
  platform-integration CI job lands. The hermetic
  `SdkRoundTripCyclesTest` covers the same matrix in-process.
- A reference JWKS-backed `BearerTokenValidator` is not bundled; this
  is intentional, so participants make a deliberate choice. A
  reference implementation can ship in a follow-up minor release.
